# Deployment Guide

This document explains how the site gets deployed to the world and how you can trigger deployments.

## 🌍 How Deployment Works

This site uses **GitHub Pages** for hosting and **GitHub Actions** for automated deployments.

### The Deployment Flow

```mermaid
graph LR
    A[Push to main] --> B[GitHub Actions Triggered]
    B --> C[Install Dependencies]
    C --> D[Build Static Site]
    D --> E[Deploy to gh-pages branch]
    E --> F[GitHub Pages Serves Site]
    F --> G[Live at anandgupta1202.github.io]
```

### Step-by-Step Breakdown

1. **You push code to `main` branch**
   - Any commit to the `main` branch triggers the CI/CD pipeline

2. **GitHub Actions runs the workflow** (`.github/workflows/ci.yml`)
   - Checks out your code
   - Sets up Python 3.11
   - Installs dependencies from `requirements.txt`
   - Caches dependencies for faster future builds

3. **MkDocs builds the site**
   - Converts all Markdown files to HTML
   - Applies the Material theme
   - Generates social cards, search index, etc.
   - Output goes to `site/` directory

4. **Deploys to `gh-pages` branch**
   - The `mkdocs gh-deploy --force` command pushes the built site to the `gh-pages` branch
   - This branch contains only the static HTML/CSS/JS files

5. **GitHub Pages serves the site**
   - GitHub automatically serves content from `gh-pages` branch
   - Available at `https://anandgupta1202.github.io`

## 🚀 How to Deploy

### Automatic Deployment (Recommended)

Simply push your changes to the `main` branch:

```bash
git add .
git commit -m "Your commit message"
git push origin main
```

The site will be live within 1-2 minutes.

### Manual Deployment (Local)

If you need to deploy manually from your local machine:

```bash
# Ensure you have dependencies installed
uv pip install -r requirements.txt

# Deploy directly to GitHub Pages
mkdocs gh-deploy --force
```

> ⚠️ **Note:** Manual deployment is generally not recommended as it bypasses the CI/CD checks.

## 🔧 CI/CD Configuration

The deployment is configured in `.github/workflows/ci.yml`:

```yaml
name: ci 
on:
  push:
    branches:
      - main           # Triggers only on main branch
permissions:
  contents: write      # Allows pushing to gh-pages
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - name: Configure Git Credentials
        run: |
          git config user.name github-actions[bot]
          git config user.email 41898282+github-actions[bot]@users.noreply.github.com
      
      - uses: actions/setup-python@v5
        with:
          python-version: 3.11
      
      # Cache for faster builds
      - run: echo "cache_id=$(date --utc '+%V')" >> $GITHUB_ENV 
      - uses: actions/cache@v4
        with:
          key: mkdocs-material-${{ env.cache_id }}
          path: .cache
          restore-keys: mkdocs-material-
      
      # Install and deploy
      - run: pip install -r requirements.txt
      - run: mkdocs gh-deploy --force
```

## 🛠️ Troubleshooting

### Build Failed

1. Check the Actions tab for error logs
2. Common issues:
   - Invalid YAML in `mkdocs.yml`
   - Broken internal links
   - Missing images or files
   - Invalid frontmatter in Markdown files

### Site Not Updating

1. Clear browser cache (Ctrl+Shift+R)
2. Check if the GitHub Action completed successfully
3. Wait 1-2 minutes for GitHub Pages cache to clear

### Custom Domain Issues

If using a custom domain, ensure:
- `CNAME` file exists in `docs/` folder
- DNS records are properly configured
- HTTPS is enabled in repository settings

## 📁 What Gets Deployed

Only the contents of the `site/` directory (generated by `mkdocs build`) are deployed:

| Source | Deployed |
|--------|----------|
| `docs/*.md` | `*.html` |
| `docs/stylesheets/` | `stylesheets/` |
| `docs/blog/images/` | `blog/images/` |
| `mkdocs.yml` | Configuration applied |
| `README.md` | Not deployed (repo only) |

## 🔐 Security Notes

- The `gh-pages` branch is auto-generated — never edit it directly
- GitHub Actions bot has write permissions only to push deployments
- Secrets should never be committed to the repository
